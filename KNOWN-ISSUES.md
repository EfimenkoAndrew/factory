# Known Issues — engine registry

This is the factory's **append-only** registry of known issues, limitations, accepted
constraints, and by-design behaviours. Read it before changing the engine; add a `KI-*`
row in the SAME change that introduces or fixes an issue. A change that adds a limitation
without a row here is the silent-divergence failure mode this registry exists to prevent.

The lib self-test (`node _workflow/lib/_selftest.mjs`) is the regression net for the
correctness-class entries — keep it green.

> This shipped registry documents the **engine invariants** only. Your own operational
> findings (per-cycle issues, host-specific quirks) accumulate here as you run the factory.

## Engine invariants & operational constraints (by design — not bugs, but must be known)

| ID | Constraint |
|----|-----------|
| KI-E1 | **No mutating git, ever** — no `commit`/`add`/`checkout`/`restore`/`stash`/`reset`/`clean` by the factory or any subagent. Fixes land on `factory/<id>` worktree branches as UNSTAGED changes; **the human commits**. |
| KI-E2 | **The Workflow runtime cannot touch the filesystem or git, cannot `require()`, and `Date.now()`/`Math.random()`/argless `new Date()` throw.** Hence the two-half split: `driver.mjs` (Node — fs/git/ledger) + `factory.js` (Workflow — agents only). Pure helpers used inside `factory.js` are inlined byte-for-byte from `_workflow/lib/`; change both copies together. |
| KI-E3 | **The filesystem is the checkpoint** (`state/ledger.json` + worktree inspection) — resumable after a kill. The ledger has a **single writer** (the driver); hand-editing it risks corruption. The findings-graph is hand-editable. |
| KI-E4 | **Scope red-lines are hard stops** — an item whose only fix would cross a scope boundary you have declared MUST `scope-stop` (→ the human queue), never be "fixed" by adding the forbidden surface. |
| KI-E6 | **Graceful-stop drain guard** — a `state/STOP_REQUESTED.md` marker puts the factory in a graceful drain: `driver.mjs group` refuses while it exists (in-flight lanes finish, nothing new launches). `fold`/`reconstruct`/`escalations` stay unguarded so running work completes. Resuming is deliberate: delete the marker (or pass `group --stop-override`). |
| KI-E7 | **Telemetry is observational, never evidentiary.** Every factory action lands as an event on the append-only stream `telemetry/data/events.jsonl` (`FACTORY_TELEMETRY=0` disables). An emitted event never feeds a fold verdict; the factory runs fine with the telemetry stack down. `driver.mjs telemetry-report` renders the evaluation report from the JSONL directly. |
| KI-E17 | **Portable mounts** — the factory is mountable at any host path (submodule or plain clone). `_workflow/lib/rootfind.mjs` detects the host repo root (walk up from the mount's parent to the first `.git`; `FACTORY_REPO_ROOT` overrides) and rewrites the committed stock-prefixed config paths onto the real mount; an optional gitignored `config/factory.config.local.json` overlays per-host knobs. See `SETUP.md`. |
| KI-E18 | **AcceptanceScan** — a pre-band clause-coverage probe: the item's `acceptance` splits into checkable clauses (`lib/acceptance.mjs`, inlined byte-identically in factory.js — change both together, the selftest pins parity); a cheap probe answers per clause "does the diff carry concrete evidence?" BEFORE the gate band. Gaps feed ONE bounded fixer amend + one re-probe; still-uncovered clauses FAIL pre-band with clause-level gateDetails. Skipped for verificationOnly + single-clause acceptances; fail-open on a null/malformed probe. |
| KI-E19 | **Evidence manifest** — `build-test.sh` trails every subcommand with a keyed `FACTORY::SUMMARY::<sub> …` marker (the suite carries its own counts); `parseVerifyRaw` prefers the keyed markers over the ambient type-agnostic dotnet summary line, so transcript append order can never misattribute counts. The fold adds a FULL-band PAIR rule: a FULL code item must show a green build marker AND a green suite signal in at least one transcript (results without `band` skip the rule — backward-compatible). |
| KI-E20 | **`driver recover <id>`** — the direct-recovery scaffold for a FAILED/ESCALATED item: dissent digest from the checkpoint's structured gateDetails, one delta re-gate prompt per dissenting role (role brief inlined), the evidence contract (integrate-raw vs mutation-proof separation + red-marker rules), the `#<cycle>r` fold skeleton (attemptsDelta:0; machine-evidence flags carried so recovery is never a lighter evidentiary path — review fix: `band` is among the carried flags, so a FULL-band prior arms the KI-E19 build+suite pair rule on the recovery fold too), and a `recovery_prepared` telemetry event. Prepare-only: the operator applies, re-gates, folds. Review fix: the fold override announces a gone/unreadable worktree (`debris/P9 diff checks SKIPPED`) instead of silently skipping the diff checks — transcript-only evidence is a visible state. |
| KI-E21 | **Sweep routing in `suggest`** — a cluster where one signature keyword spans >= 6 members (`--sweep-min` overrides) is recommended to the SWEEP band (`cluster.mjs --emit-pattern` + `driver sweep`) instead of pair-group lines — design-once + cheap applies + one pattern gate is measured ~4-10x cheaper per finding than pair lanes. |
| KI-E22 | **Acceptance-surface lint** — `graphaudit.mjs acceptanceSurfaceGaps`: path-like tokens + PascalCase type names in `acceptance` that resolve to a tracked repo file absent from `files[]` → advisory WARN at `graph-audit` and at `group` time (the file-lock cannot serialize an unlisted surface, so the fixer can be lock-forbidden from meeting acceptance). `graph-audit --fix` also appends the standards-ledger path for flagged shared-file gaps (the KI-E16 mechanical triage). |
| KI-E23 | **Telemetry completeness** — editorial verdicts are recorded in the gates map + gateDetails (advisory stays non-blocking); results and `item_folded` events carry `band` (LIGHT/FULL cost + gate-value split); the factory returns `usage` from the runtime budget counter and the fold emits a `usage` event, so cost analyses stop extrapolating from call counts. |
| KI-E24 | **`driver decisions-digest`** — one ranked page (severity x age) for the parked owner queue, with a one-line reply format (`<ID>: <letter>`) and same-target rule-together bundles; hand the digest to the owner instead of the raw queue wall. |
| KI-E39 | **Telemetry stack as a host-compose profile (documented alternative to the standalone project).** `telemetry/compose-profile.example.yaml` + a README section: the four services fold into the HOST repo's `docker-compose.yaml` under an opt-in `factory` profile — a dedicated network with aliases `exporter`/`otel-collector`/`prometheus` keeps this stack's configs byte-for-byte unmodified, no `container_name` (compose project scoping isolates hosts, so the KI-E25 collision class disappears), and host-owned ports are remapped (example: OTLP 4417/4418, Grafana 3100). Proven live in a host integration (3/3 Prometheus targets up, dashboard provisioned, session `claude_code_*` metrics flowing at the remapped port). The session env must then point at the REMAPPED OTLP port — `claude-code-telemetry.env.example` says so. |
| KI-E38 | **Real-shape seeding: a minimal test seed greens write paths that throw on real rows.** Live: a backfill endpoint's 5/5-green integration tests seeded a JSON-owned aggregate WITHOUT one of its optional owned collections; real rows carried it, and the apply path threw EF's `'…__synthesizedOrdinal' is part of a key` (whole-aggregate replacement re-parents owned-collection children) — after every gate had approved. Rule added to `test-author.md` (REAL-SHAPE SEEDING: populate every optional collection/nullable member the model declares, or justify the omission in the note) + a matching `review-testreview.md` quality check. Prompt-level only — no machinery change. |
| KI-E37 | **`gc` sweeps worktree-scoped docker-compose projects.** Agent/verify runs can `docker compose up` inside a worktree (default project name = worktree dir); removing the worktree orphans the project — live: 12 Created containers + 3 named volumes outlived their worktree. `gc` now lists (dry-run) / `down -v --remove-orphans`s (`--yes`) every compose project whose ConfigFiles ALL sit under the CONFIGURED worktrees root (`abs(cfg.paths.worktreesState)`, separator-anchored prefix per comma-joined entry — review fix: sibling dirs and hybrid host+override projects can never match; `worktree.parseComposeLs` + `strayComposeProjects`, behaviorally selftest-pinned). Best-effort: docker absent (ENOENT) → silently skipped; any OTHER enumeration failure prints a one-line SKIPPED notice (review fix — silence must not read as "no strays"). |
| KI-E36 | **The queue hints when a parked item was likely delivered in HEAD.** Delivered-in-HEAD detection existed only at graph seeding; an item ruled + hand-delivered MID-RUN sat BLOCKED with its acceptance already satisfied in HEAD (live: HOST-ITEM-A — output committed by the operator while the ledger still said BLOCKED). `escalations` AND the KI-E24 decisions-digest now carry a per-item hint when EVERY `files[]` entry has a commit newer than the park baseline — the history entry that ENTERED the parked state (`ledger.parkedAtMs`; `updatedAt` moves on later row writes — review fix), with the date logic pure + selftest-pinned (`ledger.allCommittedAfter`): "possibly DELIVERED in HEAD — verify, then `driver recover <id>`". Advisory-only (git log timestamps); never a state change; a corrupt graph disables hints with a stderr notice instead of silently (review fix). |
| KI-E35 | **Fold's KI-L65 warning distinguishes human-committed delivery from agent contamination.** KI-L65 always shouted "an agent likely wrote outside its worktree — inspect + repair", which is exactly wrong for the legitimate case of the operator committing the item's output mid-run (live: it fired on the intended human delivery of HOST-ITEM-A). The factory never commits — so drift on a path `git status --porcelain` reports clean (committed; not edited, not untracked) came via human commits: now reported as `ℹ COMMITTED DELIVERY … verify intent, no repair needed`; ANY uncommitted state — a dirty edit OR an untracked NEW file (invisible to `git diff HEAD`; the live ITEM-H5 stray-contamination shape — review fix) — keeps the ⚠ contamination wording (`mainguard.splitDriftByStatus`, behaviorally selftest-pinned; git failure → contamination, the conservative direction). Same WARN-only posture; still never blocks the fold. |
| KI-E34 | **`recover` handles BLOCKED (owner-ruling recovery).** Resolving a ruled BLOCKED item previously required internals surgery: hand-edit the graph, know that BLOCKED's only legal edge is → READY, hand-author a recovery fold with the `#<cycle>r` resultId + the full CLAIMED re-entry chain (live: HOST-ITEM-A took exactly that). `recover <id>` now accepts BLOCKED and scaffolds the protocol with the BLOCKED-specific steps spelled out: record the ruling on the graph item (`ownerDecision` + `ownerDecisionResolved: true`, ratified files into `files[]`), run `driver reset <id>` BEFORE the fold, and — when the ruling ratifies already-delivered work — the prior round's transcripts stand as evidence. `recoveryTransitions('BLOCKED')` = the full 10-hop chain (selftest-pinned). The fold's deterministic evidence override applies unchanged — a BLOCKED recovery is never a lighter evidentiary path (review fix: a prior-less skeleton — the never-ran seed-BLOCKED shape — FILL-prompts `codeChange`; unfilled reads truthy, so the override demands full code evidence and fails closed instead of silently taking the doc/config no-evidence path; the scaffold spells out the never-ran protocol, and `recover` explains the run-recover-before-reset ordering when refused). |
| KI-E33 | **A run's cost/token telemetry is silently NOT gathered unless the session opts in — now surfaced at preflight.** The dashboard's two cost panels read `claude_code_token_usage_*`, emitted by the **Claude Code session** (via OTLP), not by the factory. If the session was launched without `CLAUDE_CODE_ENABLE_TELEMETRY=1` + `OTEL_EXPORTER_OTLP_ENDPOINT`, an entire run's token telemetry is lost with no cue — `factory_*` metrics (driver/agent-stage/fold/transition/aggregate-usage from `events.jsonl`) still land, so it looks like telemetry "worked" (live: two full cycles gathered `factory_*` but zero `claude_code_*`). `preflight` now reports `cost telemetry: ready → <endpoint>` or `NOT gathered — <reason>` (`costTelemetryReady`, pure/selftest-covered — review fix: `ready` also requires `OTEL_METRICS_EXPORTER` to include `otlp`, because Claude Code has NO default metrics exporter and enable+endpoint alone export nothing; the metrics-specific `OTEL_EXPORTER_OTLP_METRICS_ENDPOINT` counts; a missing `OTEL_EXPORTER_OTLP_PROTOCOL` rides as a caution on ready; every missing var is named; `FACTORY_TELEMETRY` is no longer consulted — it mutes only the factory's own events.jsonl, an independent plane), and the `/ai-factory` session-start step tells the operator to fix it before running (set the env — `telemetry/claude-code-telemetry.env.example`, KI-E28 — or put it in the host's `.claude/settings.local.json` `env`). The collector→Prometheus path itself was already correct (verified by pushing a synthetic OTLP metric end-to-end); the gap was purely session opt-in with no warning. |
| KI-E31 | **`fold` accepts the Workflow harness envelope directly.** The runtime wraps the factory's return as `{summary, agentCount, logs, result:{mode,cycle,results:[…]}}`, so a raw task-output file carries the fold payload under `.result`. `cmdFold` read `results.results` at the top level → `undefined` → it silently folded **0** items, forcing the operator to hand-extract `.result` into a file every cycle. `unwrapResultEnvelope` (pure, in `ledger.mjs`, selftest-covered) now unwraps that one shape; a direct results file (array, or an object already carrying `.results`) passes through unchanged. `fold <task-output-file>` now Just Works. Review fix: a ZERO-result payload (crashed/empty-run envelope, or an unexpected shape) no longer folds with success affect — loud error, exit 1, no cycle bump, no ledger write. |
| KI-E32 | **Acceptance-surface lint (KI-E22) no longer flags references/citations/exclusions.** The lint nudges files named in `acceptance` but absent from `files[]`. It fired on every run for files the item names to *model on*, *cite* (`SomeEndpoint.cs:739`), or *exclude* (`do NOT touch SomeHelper`) — none of which the file-lock should serialize. `acceptanceSurfaceGaps` now skips a token whose immediate context carries a strong reference cue (`modeled on`, `same … uses`, `File.cs:NN` citation, `do not touch`, `non-goal`, `rules out`, `instead of`, …). Deliberately conservative: an actively-named edit target (`ItemsController clamps …`, `modify X`, `in X`) still surfaces, so genuine "you forgot file X in the lock-set" gaps stay visible. Review fix: the cue set was TIGHTENED — bare `existing`/`see`/`per` and trailing `uses`/`does`/`already` suppressed everyday ACTIVE phrasings ("the existing X must clamp", "X does not clamp", "X uses raw Skip; fix it"); clause stops (`;:!?`) now end a cue's reach, and a bare `TypeName.cs:NN` citation is recognized (previously only pathed citations were). Both directions selftest-pinned. |
| KI-E29 | **A CLOSED dependency whose fix is uncommitted provides no code to dependents.** Worktrees branch from HEAD, and fixes stay UNCOMMITTED on `factory/<id>` branches (KI-E1) — so a dependency being `CLOSED` in the ledger does *not* put its code in HEAD until the human commits it. A dependent scheduled before that commit builds from a HEAD missing the dependency's code (live: `HOST-ITEM-A` depended on CLOSED-but-uncommitted `HOST-ITEM-B`; the fixer correctly re-derived HOST-ITEM-B's missing method fix inside its own worktree, which then tripped a false lock-set/scope block — KI-E30). `group` now WARNs when a picked item depends on a CLOSED item that still has a live worktree (proxy for "not yet committed to HEAD"); it does not exclude (nothing is clobbered — the owner decides whether to commit the dependency first for a clean base). Distinct from KI-E14, which is about the *main tree's* uncommitted overlap. Review fix: the check reads the LEDGER ROW's recorded `worktree` path (pure `ledger.closedDepsWithLiveWorktree`, selftest-pinned) instead of an assumed `state/worktrees/<id>` dir — SWEEP-closed deps are covered too, and gc (which nulls the field) correctly ends the warn. |
| KI-E30 | **`scopeViolation` conflated a lock-set deviation with a product-scope red-line.** The shared gate schema's `scopeViolation:true` is meant for the one hard-stop — a `product-scope.md` red-line (tax/purchase-fee/SAR/gov-report/shipping). But nothing told gates that touching a file *outside the item's declared `files[]` touch-set* is NOT that, so the developer gate set `scopeViolation:true` for a justified 1-line companion fix outside the lock-set, and `factory.js`'s KI-L57 guard (non-APPROVED + scopeViolation → hard block) framed it to the owner as a "product-scope violation" — a false-premise block on green, fully-reviewed code (live: `HOST-ITEM-A`). Fixed in the shared gate prompt: `scopeViolation` means a product-scope red-line ONLY; a touch-set deviation is a normal `finding` (note whether justified) and the verdict rests on its merits. The lock-set-overlap *observation* remains valuable — it stays a finding, it just no longer masquerades as a red-line hard-stop. Follow-up (same live case): when the hard stop DOES fire, `factory.js` echoes the flagging gate's own headline into the block reason AND the queue note keeps that raw reason verbatim — bracketed after the decision-framer's headline when framing succeeds, bare otherwise (review fix; previously the framer's paraphrase could displace the gate headline from the note) — so a mislabelled block is self-evident from the queue. |
| KI-E28 | **Dashboard cost panels need session-side OTLP.** The Grafana dashboard's two cost panels (`Claude Code token rate by type`, `Prompt-cache hit ratio`) read `claude_code_token_usage_tokens_total`, which the **Claude Code session** emits — not the factory exporter. The collector was already wired to accept it (`otel-collector.yaml` metrics pipeline has an `otlp` receiver; :4318 exposed), but nothing configured the session, so the panels were permanently empty with no cue why. Fixed as a setup step, not code: `telemetry/claude-code-telemetry.env.example` + a `telemetry/README.md` section give the exact env (`CLAUDE_CODE_ENABLE_TELEMETRY=1`, `OTEL_METRICS_EXPORTER=otlp`, `OTEL_EXPORTER_OTLP_ENDPOINT` → the collector's host HTTP port). Also documented: the `Span-derived stage latency p90` panel is live-only (spans push only while the exporter runs — AD-13), whereas the exporter-histogram `Stage duration p95` panel is the always-populated duration authority. Every `factory_*` panel needs none of this. |
| KI-E27 | **Multi-source issue ingestion.** `driver ingest` pulls work-items into `state/normalized/<source>.json` (which `merge-graph` folds) from `--github owner/repo` (`--issues` csv or `--label`/`--state`/`--limit`, via the `gh` CLI), `--json` (gh-issue array or ready work-item passthrough), or `--markdown` (a `- [ ]` checklist). The mapping is the pure lib `_workflow/lib/ingest.mjs` (selftest-covered — label→severity/theme, section extraction, id shape); the driver does the I/O (KI-E2 split). **Honest-acceptance invariant:** an ingested item is never `auto` — `blocked` triage when no acceptance section is parseable, at most `escalate` when an "Expected behaviour" section is lifted (a human still confirms it). A raw issue rarely states a checkable acceptance + regressionTest, so ingestion seeds the queue and a human/`bmad-spec` authors the contract before it schedules; it never fabricates a green light. Replaces the SETUP.md §6 "no adapter ships" gap. Review fixes: the invariant is ENFORCED at the command too — `enforceIngestTier` clamps `--json` passthrough tiers (auto/missing → escalate/blocked; selftest-pinned) so merge-graph's auto-default can never see an ingested item, and merge-graph now prints a VERIFY problem line when a hand-authored file's tier defaults to auto; flags are validated loudly up front (`--severity`/`--id-prefix`/`--issues`), gh failures exit 1 with the stderr reason, a --limit-sized result warns of likely truncation, `--out` is sanitized to a plain in-dir name, malformed `--json` elements are counted + skipped instead of crashing; the markdown adapter ingests UNCHECKED boxes only (a checked `[x]` is done work — skipped, count reported) with CONTENT-HASHED ids (stable under backlog edits; positional ids re-attached ledger state to different tasks), and `ingestReport.other` guards the "none are auto-runnable" line. Provenance cites the actual matched heading; fenced code no longer truncates section lifts; severity/theme label boundaries hardened (`not-critical`, `P10`, `docker`). |
| KI-E26 | **Host data must never enter the engine repo.** `SETUP.md` promises "everything under `state/`, `reports/`, and `queue/` is generated per host at runtime and is gitignored, so no project data ever enters this repo" — but `queue/decisions.md` was **tracked**, and `state/{ledger,findings-graph,PROGRESS}` + `reports/*` were merely untracked (so `git add -A` in the mount swept them in). Operating the factory in a host therefore dirtied a tracked file with that host's data: the decision queue quotes owner framings verbatim, which routinely name customers, internal issue ids and production detail. `queue/decisions.md` is now untracked (`queue/.gitkeep` ships instead, matching `state/`/`reports/`) and the per-host runtime artifacts are gitignored, making the shipped promise true. Nothing reads these as input — `setup/init.mjs` scaffolds the dirs and `driver init`/`escalations` regenerate the files on every host. |
| KI-E25 | **Telemetry stack identity is per-host, not just per-port.** The factory mounts in any number of host repos, but `telemetry/docker-compose.yml` pinned `container_name: factory-*` and the compose project `name:`, so a SECOND host on the same machine could not start its stack at all (duplicate container names — and `docker compose -p` does **not** override `container_name`), and the project name scopes the `prometheus-data`/`grafana-data` volumes, so a renamed-by-hand host would silently share host A's data. Both are now `${FACTORY_COMPOSE_PROJECT:-ai-factory-telemetry}` / `${FACTORY_CONTAINER_PREFIX:-factory}`, defaulting to the historical names (existing single-host stacks unaffected). Host B sets both in `.env` alongside the ports — see `telemetry/README.md`. Verified by running two stacks concurrently. Prometheus scrapes by **service** name (`exporter:9464`), never `container_name`, so inter-service DNS is unaffected. |

## Verified design properties (recorded so they are not re-investigated)

- The global agent limiter cannot deadlock — every `agent()` routes through one limiter; an
  item never holds a slot while awaiting another.
- Per-item results are isolated — a thrown item degrades to `FAILED`; siblings still
  complete and fold (the batch never rejects as a whole).
- A null/again-null gate result fails closed (`!== 'APPROVED'` → `FAILED`).
- `foldResults` is idempotent and self-heals a partial application (it re-walks from the
  current state rather than corrupting it).

## How to add an entry

Give it a stable `KI-<class><n>` id, one row stating the issue/constraint and its
mitigation or status, and — if it is a correctness fix — a matching assertion in
`_workflow/lib/_selftest.mjs`. Resolved entries stay (marked resolved), never deleted.
